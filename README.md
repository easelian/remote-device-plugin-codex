# Remote Device Integrations

This repository prepares Remote Device Hub for ChatGPT web and Codex desktop. The public submission source declares the MCP endpoint and OAuth dynamic client registration, without a personal registered connection ID. Each user authorizes their own Hub account and pairs their own devices.

The standalone Codex package is version 1.3.1. Its `mcp.json` contains the server type and URL only: Codex 0.163/0.164 rejects the portal's per-server `extensions` field and otherwise silently omits the MCP server. Codex discovers OAuth from the Hub's authentication challenge and resource metadata. The public submission source in `public/` retains the explicit OAuth DCR declaration.

```sh
npm run package:standalone
npm run check:codex
```

The loader check must report `loaded_mcp_servers: ["remote-device-hub"]` and `passed: true`. It does not install the plugin, authorize a Hub account, or call a device tool. After updating the installed plugin, verify authorization and an actual `list_devices` call as well.

The public release is **not yet published or verified with a clean ChatGPT/Codex account**. The author-upload ZIP is an input to the official public submission workflow, not a proven direct desktop installer. Portal-generated connection bindings belong to the finalized release; do not copy a developer account's private binding into the upload.

```sh
npm ci
npm test
npm run style:check
npm run package:draft
```

The explicit draft command writes `dist/remote-device-hub-public-1.3.0-draft.zip` and its readiness report. `npm run package` is the strict publication-materials build and fails while required package fields are missing. Package validation does not establish publisher verification, review approval, publication, or client acceptance.

## Code style

`npm run format` formats development scripts and tests. `npm run style:check` checks formatting and lint rules; `npm run lint` runs only the linter. Biome is pinned as a development dependency. Use two-space indentation, single quotes, semicolons, trailing commas, one statement per line, and explicit type imports. Explicit `any` and `@ts-ignore` are prohibited. Plugin manifests, assets, generated build output, and fixed test fixtures are excluded from formatting.

Manifests and release records are parsed into domain types while retaining existing fields and serialization order. ZIP construction preserves the existing format. Fixed fixtures generated by the legacy Python tools verify file hashes and archive bytes independently of current listing copy.

## Deployment addresses

The MCP URLs in `plugins/remote-device-hub/mcp.json` and
`public/remote-device-hub/mcp.json`, plus the public listing URLs, are generated
from the Server repository's `deploy/config.json`. With sibling checkouts, run:

```sh
python3 ../remote-device-server/scripts/sync-deployment.py
python3 ../remote-device-server/scripts/sync-deployment.py --check
```

Commit/release the generated manifests with the plugin. Builds of this repository
remain independent of the Server checkout. A standalone checkout can use
`--project remote-device-plugin-codex` with the generator and an explicit
`--workspace` parent directory. Existing installed account Apps are not changed
by regenerating these source manifests; update their registered endpoint through
the normal publication workflow after validating the new deployment.
