# 跨账号发行与双端验收

1.3.0 的目标是：没有开发者现有连接的用户，能从同一个公开插件入口在 ChatGPT 网页和 Codex 桌面安装，授权自己的 Hub 账户并配对自己的设备。当前已完成源码及服务端验证，公开发行和干净客户端账号验收尚未完成。

## 发行方式

默认源码采用 `public/remote-device-hub/plugin.json` 和 `mcp.json`，声明 `https://rdh.easelian.com/mcp`、OAuth 动态客户端注册及 `devices:control`。上传包不包含 `.app.json`、私人 App ID、授权头或凭据。官方发布流程中的连接注册和最终安装包生成仍需完成。

当前 Codex 实际解析器会拒绝独立 `mcp.json` 的 OAuth 扩展，因此作者上传 ZIP 不能直接作为已验证的桌面安装包。最终必须测试平台生成的同一公开发行版本，不能拿上传格式检查或既有 OAuth 缓存代替安装验收。

`npm run package:draft` 明确生成未完成材料的草稿；`npm run package` 在必填材料缺失时失败。发布者按用户指定填写 EaseLian，公司身份验证仍由平台确认。

## 已完成的证据

| 检查 | 结果 | 证据与边界 |
| --- | --- | --- |
| 插件源码测试 | 35 项通过，格式与 lint 通过 | 包内私人身份引用拒绝、元数据约束、默认发行路径及历史字节兼容性 |
| 服务端账号与 MCP 测试 | 39 项通过 | 新用户隔离、身份、公开协议及 MCP 会话；Google 身份使用模拟服务 |
| 真实 Node Agent 首次接入 | 1 项通过 | 两个新 Hub 用户共用 OAuth 客户端；空列表、用户配对、实际文件创建和按哈希修改、命令输出及退出状态、跨用户访问拒绝、重新授权后设备仍归属原用户 |
| 公开页面与协议发现 | 已读取 | 网站、支持、隐私、条款及 OAuth/resource metadata 可访问；生产登录页面提供 Google 首次注册说明 |
| 干净 ChatGPT 账号安装及调用 | 未运行 | 当前没有测试账号，公开发行尚未完成 |
| 干净 Codex 账号安装及调用 | 未运行 | 必须使用最终公开版本，不复用开发者连接或 OAuth 缓存 |

真实 Node Agent 测试运行在临时服务与文件目录中，不修改生产设备。它没有执行真实 Google 登录，也没有经过 ChatGPT/Codex 客户端。五个正例、三个反例的宿主模型审核用例仍需单独运行。

## 完成条件

1. 完成 EaseLian 公司验证，确认平台记录与公开发布者信息一致。
2. 准备独立审核账户及样例设备，审核员无需开发者邮箱、电话或私人网络即可登录。
3. 在真实宿主中演示声明的版本，录制并验证可播放的审核视频；填写实际链接。
4. 将完整包上传官方发布平台，核对元数据、OAuth 连接、审核用例、扫描和法律声明，再按授权提交审核及发布。
5. 在未安装该插件、未建立其连接的账号中，从同一公开入口分别安装到 ChatGPT 和 Codex，完成首次 OAuth、空列表、配对、读写与命令测试；验证两个 Hub 用户互相不可见。

截至本次准备，未上传公开草稿、未提交审核、未发布。已有 1.2.9 的同账号双端结果见 [更新记录](../CHANGELOG.md#129)，只用于开发回归。
